# K5 — Import riconciliazione multi-sede · morosi ticket con la sede · scope della GET ticket

Contratto delle tre route toccate da K5 (2026-09-26). Serve a chi scrive le interfacce
dell'ondata 2 (Riconciliazione, pannello Ticket).

## 1. `POST /api/pagamenti/riconciliazione` — import dell'estratto conto

**Prima**: `resolveScuolaScrittura` → con più sedi e nessuna dichiarata **400
`SEDE_DA_SPECIFICARE`**. La segreteria delle tre sedi non poteva importare.

**Ora**: il registro è unico per le tre sedi e i movimenti nascono con `scuola_id` null, quindi
la sede **non si chiede**. Il controllo è il PERIMETRO dell'operatore (`resolveScuoleAttive`).

### Corpo

Invariato (multipart `file` + `mapping?`, oppure JSON `{ contenuto, filename?, mapping? }`).
`scuola_id` è **facoltativo** in entrambi i rami:

| `scuola_id` | esito |
|---|---|
| assente, `null`, `''` | nessuna sede dichiarata → l'import procede |
| uuid dentro le sedi attive (anche in maiuscolo) | procede |
| uuid **fuori** dalle sedi attive | **403** `{ codice: 'SEDE_NON_ACCESSIBILE' }` + `warn` `import-sede-non-accessibile` |
| il testo `"undefined"` / `"null"` (qualunque maiuscola, spazi ammessi) | **422** `{ codice: 'CORPO_NON_VALIDO' }` (codice già dichiarato e tradotto: «ricarica la pagina e riprova») + `warn` `import-sede-testo-non-valido` |
| altra stringa non uuid | 400 di validazione (`Dati non validi`), come prima |

**Indicazione per l'interfaccia**: con più sedi attive **omettere** `scuola_id` (o mandarlo
vuoto). Mai `String(undefined)`.

### Perimetro

- sedi attive vuote → **403** `SEDE_NON_ACCESSIBILE` + `warn` `import-senza-sedi-attive`
  (uno scope vuoto nega, non allarga);
- il controllo avviene **prima** di interpretare il file (passo 3 dell'ordine della route).

### Scritture

- `riconciliazione_import.scuola_id` e `riconciliazione_movimenti.scuola_id` → **null**
  (invariato).
- **Ripiego del DB E2E della CI** (`scuola_id` ancora NOT NULL → `23502`): si ritenta con
  `sedeRipiegoCi` = la sede dichiarata (forma canonica di `restringiSedi`) se c'è, altrimenti
  la **prima delle sedi attive**. Log `info` `degradazione_scuola_id_import` /
  `degradazione_scuola_id_movimenti` invariati. In produzione non scatta.
- **Audit** (`logScrittura`, `riconciliazione_import`/`insert`): la riga di
  `audit_scritture_docente` nasce con **`scuola_id` NULL**, anche quando l'operatore ha una sede
  primaria e anche quando il corpo dichiara una sede. Poiché `logScrittura`
  (`src/lib/audit/scrittura.ts:112`) scrive `input.scuolaId ?? attore.scuola_id ?? null` — il
  `??` tratta il null esplicito come assente — la route passa
  `attore: { ...auth.user, scuola_id: null }` oltre a `scuolaId: null`. `attore_id` e
  `attore_ruolo` restano quelli veri (dell'attore `logScrittura` legge solo `id`, `role`,
  `scuola_id`). Verificato sulla **riga scritta** (non sull'argomento) in
  `__tests__/api/pagamenti-riconciliazione-import-multisede.test.ts`, col `logScrittura` vero.

### Risposta di successo

Invariata.

## 2. `GET /api/pagamenti/ticket/morosi`

Ogni riga di `data[]` ha due campi in più:

```ts
{
  alunno_id: string
  nome: string
  cognome: string
  classe_sezione: string | null
  scuola_id: string | null      // NUOVO — la sede dell'ALUNNO (ticket_mensa non ne ha una)
  scuola_nome: string | null    // NUOVO — da `scuole.nome`; null se la lettura dei nomi fallisce
  saldo_ticket: number
  ultimo_carico: string | null
}
```

- I nomi si leggono con **una** query `scuole.select('id, nome').in('id', <sedi presenti
  nelle righe>)`: nessuna sede oltre al perimetro. Se fallisce: righe restituite lo stesso con
  `scuola_nome: null` e `warn` `nomi_sede_non_letti`.
- Errore sulla SELECT dei morosi → **500** `{ error: 'Errore caricamento morosi ticket',
  codice: 'LETTURA_FALLITA' }` loggato con `logErrore` (prima non si loggava, non aveva codice,
  e il corpo portava `details: error.message`: tolto). Stessa risposta della route gemella
  `GET /api/pagamenti/ticket` allo stesso guasto. Debito pagato nell'allowlist
  `errori-senza-codice`: voce `ticket/morosi/route.ts` 2 → 1, `totale_occorrenze` e
  `MAX_OCCORRENZE` 1375 → 1374 (la risposta rimasta senza codice è il 500 generico del `catch`
  esterno, non toccato da K5).
- Il parametro `scuola_id` della query resta **consultivo** come prima (il perimetro è
  `resolveScuoleAttive`): non è stato cambiato.

## 3. `GET /api/pagamenti/ticket?alunno_id=`

- **Staff** (`admin`/`coordinator`/`segreteria`): ora passa da `assertAlunnoInScope` — la
  stessa guardia della POST. Alunno fuori dai plessi dello staff → **403**; inesistente →
  **404**; scope non risolvibile → 5xx. In tutti questi casi `ticket_mensa` **non viene letto**.
- **Genitore**: invariato (`genitoreHasFiglio`, 403 se non è suo figlio).
- Errore sulla SELECT di `ticket_mensa` → **500** `{ codice: 'LETTURA_FALLITA' }` loggato (prima diventava «saldo 0»). Nessuna
  riga resta `{ alunno_id, saldo_ticket: 0, ultimo_carico: null }`.
