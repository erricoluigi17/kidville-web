# Contratto D1 — Orario delle attività nel diario

Consumatori: **D2** (editor: `ActivityDetailInline`, `DiaryEventEditor`) e **D3** (diario del
genitore, `parent/diary/page.tsx`). Nessuna migrazione: i campi vivono nel jsonb `eventi_diario.dettagli`.

## Dati

In ogni voce di `dettagli.activities[]` di un evento con `tipo_evento = 'attivita'`:

| campo | tipo | obbligatorio | semantica |
|---|---|---|---|
| `ora_inizio` | `"HH:MM"` (24 h, zero davanti: `00:00`–`23:59`) | no | ora in cui **quella** attività è iniziata |
| `ora_fine` | `"HH:MM"` (idem) | no | ora in cui **quella** attività è finita |

- Ogni attività ha il **suo** orario. Inizio e fine sono facoltativi **ciascuno per conto suo**
  (solo inizio, solo fine, entrambi, nessuno).
- «Non inserito» = campo **assente**, `""` oppure `null`: tutti e tre ammessi dal server. È ciò che
  un `<input type="time">` vuoto produce, quindi l'editor può mandarlo così com'è.
- Formato: esattamente `HH:MM` (regex `ORA_ATTIVITA_RE = /^([01]\d|2[0-3]):[0-5]\d$/`). **Non**
  `9:30`, **non** `09:30:00` (niente `step` sui secondi negli input).
- Se ci sono entrambi: `ora_fine >= ora_inizio` (uguali ammessi). Niente attività a cavallo della
  mezzanotte.
- Gli altri campi della voce (`tipo`, `descrizione`, `partecipazione`) non cambiano.

Esempio:
```json
{ "activities": [
  { "tipo": "pittura", "descrizione": "…", "partecipazione": "entusiasta", "ora_inizio": "10:00", "ora_fine": "11:00" },
  { "tipo": "musica",  "descrizione": "…", "ora_inizio": "", "ora_fine": null }
] }
```

## Helper (`src/lib/diary/attivita.ts`, puri)

- `type VoceAttivita` — `{ tipo?, descrizione?, partecipazione?, ora_inizio?, ora_fine? }`.
- `ORA_ATTIVITA_RE`, `oraAttivitaValida(v): v is string`.
- `orarioAttivita(voce: unknown) → { inizio: string | null; fine: string | null }` — normalizza per
  la **lettura**: assente / `""` / fuori formato → `null`; spazi intorno tolti. Mai lancia.
  Per la frase del genitore («dalle 10:00 alle 11:00», «dalle 10:00», «fino alle 11:00») si parte
  da qui; le parole stanno nei `messages/*/diario.json` di D3.
- `oraDiLatoAttivita(dettagliOVoce: unknown, timestampSalvataggio?: unknown) → string | null` —
  l'ora da mostrare **a lato** della voce: l'`ora_inizio` di **`activities[0]`** se valida,
  altrimenti `null`. **Non** si cerca la prima attività che ha un orario: se la prima non ce l'ha,
  `null`. Con `null` il chiamante mostra l'**ora del salvataggio** come oggi, formattata da lui
  (fuso/locale della pagina); il secondo argomento è accettato ma non usato. Accetta sia
  `dettagli` sia la voce intera `{ dettagli }`.
- `attivitaCompilata(dettagli)` — **invariata**: un orario da solo **non** è contenuto. Una voce con
  solo `ora_inizio`/`ora_fine` e senza descrizione né partecipazione resta muta, e il server la salta
  (`voci-mute-saltate`) come prima.

## Server — `POST /api/diary/entries`

- Per ogni evento `tipo_evento = 'attivita'` con `dettagli` oggetto (non array: un `dettagli` array o
  primitivo passa com'era prima), si validano con zod
  `activities[].ora_inizio`/`ora_fine`. Tutto il resto di `dettagli` resta pass-through, e si scrive
  il `dettagli` **ricevuto** (i `""` non vengono riscritti).
- Validazione **prima** di qualunque lettura/scrittura sul DB, sull'**intero lotto**: una voce
  sbagliata ⇒ nessuna riga scritta.
- Errore ⇒ **422**:
  ```json
  { "error": "<messaggio italiano>", "codice": "ORARIO_ATTIVITA_NON_VALIDO | ORARIO_ATTIVITA_INCOERENTE",
    "details": [{ "path": "0.dettagli.activities.1.ora_fine", "message": "…" }] }
  ```
  - `ORARIO_ATTIVITA_NON_VALIDO`: formato non `HH:MM` (o tipo non stringa).
    Messaggio: «Orario dell'attività non valido: usa il formato HH:MM (es. 09:30).»
  - `ORARIO_ATTIVITA_INCOERENTE`: fine prima dell'inizio, valutato **solo se entrambi** gli orari
    della voce sono `HH:MM` validi (`'9:30'`→`'10:00'` dà soltanto l'errore di formato su
    `ora_inizio`, mai un'incoerenza). Ha la precedenza se nel lotto ci sono entrambi i tipi
    d'errore; `details` li elenca tutti. Messaggio: «L'ora di fine di un'attività non può essere
    prima dell'ora di inizio.»
  - `path`: con body **array** inizia con l'indice dell'evento (`0.dettagli…`); con body **oggetto
    singolo** inizia da `dettagli…`.
- Log: `logEvento('diary', 'warn', { operazione: 'diary/entries:POST', esito:
  'orario-attivita-non-valido', error_code, n_voci_non_valide, n_ricevute })` — solo codici e
  conteggi, nessun alunno né testo. `n_voci_non_valide` conta le **voci** (una voce con inizio e
  fine entrambi sbagliati vale 1), `n_ricevute` gli eventi del body.
- Gli altri `tipo_evento` non vengono toccati da questa regola.

Suggerimento per D2: impedire in editor `fine < inizio` (stesso confronto fra stringhe `HH:MM`) e
mostrare comunque `error` della 422 se arriva.
