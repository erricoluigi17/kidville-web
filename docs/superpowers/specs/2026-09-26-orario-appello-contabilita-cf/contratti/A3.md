# Contratto A3 — `api/primaria/appello`: ritardo / uscita anticipata giustificati

Rotta: `src/app/api/primaria/appello/route.ts`. Colonna: `presenze.assenza_oraria_giustificata`
(migrazione `20260926100000_presenze_assenza_oraria_giustificata.sql`, con CHECK
`presenze_giustificata_con_nota` e trigger che spegne il flag fuori da ritardo/uscita).

## POST `/api/primaria/appello`

Singolo:

```json
{
  "sectionId": "<uuid>",
  "data": "YYYY-MM-DD",
  "alunnoId": "<uuid>",
  "stato": "ritardo",
  "orarioEntrata": "10:05",
  "noteAppello": "Terapia",
  "assenzaOrariaGiustificata": true
}
```

In blocco: `{ sectionId, data, records: [ { alunnoId, stato, orarioEntrata?, orarioUscita?, noteAppello?, assenzaOrariaGiustificata? }, … ] }`.

| Campo | Tipo | Note |
|---|---|---|
| `assenzaOrariaGiustificata` | `boolean`, opzionale | **Assente = `false`.** Un valore non booleano (`"si"`, `1`) è un **400** (`Dati non validi`). |
| `noteAppello` | `string \| null`, opzionale | Invariato: se il corpo non lo nomina, la nota esistente si conserva; `null` esplicito la cancella. |

### Regole (422, dopo la validazione di forma)

Controllate record per record; nel blocco **basta un record sbagliato** perché non si scriva niente.

| Condizione | Stato | `codice` | `error` |
|---|---|---|---|
| flag `true` e `stato` ∉ {`ritardo`, `uscita_anticipata`} | 422 | `GIUSTIFICAZIONE_STATO_NON_AMMESSO` | «Si possono giustificare solo un ritardo o un’uscita anticipata.» |
| flag `true` e `noteAppello` assente, `null`, vuota o di soli spazi | 422 | `GIUSTIFICAZIONE_SENZA_NOTA` | «Per giustificare il ritardo o l’uscita anticipata serve una nota con il motivo.» |

La nota va mandata **nello stesso corpo** del flag: una nota già salvata non basta.

### Che cosa si scrive

- `assenza_oraria_giustificata` si scrive **sempre** nell'upsert: `true` solo se il record porta
  `assenzaOrariaGiustificata: true` su `ritardo`/`uscita_anticipata`, altrimenti `false`.
- ⚠️ **Conseguenza per il client (A4)**: ogni POST che riguarda un alunno con la giustificazione
  accesa deve **rimandare** `assenzaOrariaGiustificata: true` (e la nota), altrimenti la spegne.
  È voluto: una correzione (stato, orario, «Tutti presenti») che non la nomina la toglie.
- Stato e orari non cambiano per effetto del flag: l'alunno resta in `ritardo`/`uscita_anticipata`.

### Risposta 200

Invariata: `{ success: true, data: [righe salvate] }`; ogni riga ora porta anche
`assenza_oraria_giustificata`.

### Log

`logEvento('registro', 'info', …)` dopo l'upsert riuscito, un evento per alunno:

- `esito: 'assenza-oraria-giustificata-salvata'` quando la riga è salvata con il flag acceso;
- `esito: 'assenza-oraria-giustificata-rimossa'` quando era acceso e ora è spento.

Campi: `operazione: 'primaria/appello:POST'`, `alunno` (uuid), `sezione` (uuid), `stato`. **Mai** il
testo della nota: è il motivo, spesso sanitario, di un minore.

## GET `/api/primaria/appello?sectionId=&data=`

Per ogni alunno della sezione (anche senza riga di presenza), oltre ai campi esistenti:

| Campo | Tipo | Senza riga |
|---|---|---|
| `note_appello` | `string \| null` | `null` |
| `assenza_oraria_giustificata` | `boolean` | `false` (mai `undefined`) |

Esempio di elemento:

```json
{
  "id": "<uuid alunno>",
  "nome": "…",
  "cognome": "…",
  "presenza_id": "<uuid> | null",
  "stato": "ritardo",
  "note_appello": "Terapia",
  "assenza_oraria_giustificata": true,
  "orario_entrata": "2026-09-26T08:05:00+00:00",
  "orario_uscita": null,
  "giustificata": false,
  "giustificazione_testo": null,
  "giust_vista_il": null,
  "appello_fatto": true,
  "presa_visione_annullabile": false
}
```
