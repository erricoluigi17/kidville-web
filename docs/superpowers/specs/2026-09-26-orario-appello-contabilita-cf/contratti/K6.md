# K6 — Filtro per classe della contabilità (contratto)

Decisione del titolare: il filtro è a **selezione multipla**, e con più sedi le classi omonime
restano **separate per sede** («Sezione A — Giugliano», «Sezione A — Aversa»). Una classe è un
**`section_id`**, mai un nome.

## `src/lib/pagamenti/filtro-classi.ts` (puro, nessuna dipendenza)

```ts
type ClasseFiltro = { id: string /* section_id */; nome: string; scuolaId: string; scuolaNome: string };

classiDaAlunni(
  alunni: ReadonlyArray<{ section_id: string | null; classe_sezione: string | null; scuola_id: string | null }>,
  nomiSedi: Record<string, string>,
): ClasseFiltro[]
etichettaClasse(c: ClasseFiltro, mostraSede: boolean): string
filtraPerClassi<T>(righe: ReadonlyArray<T>, selezionate: ReadonlyArray<string>, sectionIdDi: (r: T) => string | null): T[]
const NOME_CLASSE_ASSENTE = '—'
```

Esportati: `ClasseFiltro`, le tre funzioni e `NOME_CLASSE_ASSENTE`. Il separatore `' — '` è una
costante interna al modulo. `NOME_CLASSE_ASSENTE` è un **segnaposto**, non un testo da mostrare: è
esportato perché l'interfaccia lo riconosca e lo sostituisca con un testo tradotto (vedi il
componente, «Classe senza nome»).

| Funzione | Comportamento |
|---|---|
| `classiDaAlunni` | Una voce per `section_id` distinto. Alunni con `section_id` nullo **esclusi**. Ordine: nome della sede, poi nome della classe in ordine naturale (`localeCompare('it', { numeric: true })`: «Sezione 2» prima di «Sezione 10»). `nome` = primo `classe_sezione` non vuoto (trim) fra gli alunni della classe, altrimenti `NOME_CLASSE_ASSENTE` (`'—'`). `scuolaNome` = `nomiSedi[scuola_id]`, **stringa vuota** se la sede non è nella mappa (nessun nome inventato). |
| `etichettaClasse` | `mostraSede=false` → `"Sezione A"`; `mostraSede=true` → `"Sezione A — Giugliano"`. Con `scuolaNome` vuoto resta `"Sezione A"` (niente trattino appeso). |
| `filtraPerClassi` | `selezionate` vuota → **tutte** le righe (copia), anche quelle senza classe. Altrimenti le righe il cui `sectionIdDi(r)` è fra le selezionate; una riga con `null` è esclusa. Non muta l'input. |

## `src/components/features/admin/pagamenti/FiltroClassiContabilita.tsx`

```tsx
<FiltroClassiContabilita
  classi={ClasseFiltro[]}        // già ordinate: passare l'uscita di classiDaAlunni
  selezionate={string[]}         // section_id scelti; [] = «Tutte le classi»
  onChange={(ids: string[]) => void}
  mostraSede={boolean}           // true quando le sedi VISIBILI sono più di una: effettive.length > 1
  className?={string}
/>
```

- **`mostraSede` si calcola da `useSediAttive().effettive`, MAI da `selezionate`.** In
  `src/lib/context/sede-context.tsx` `selezionate` vuoto significa «TUTTE le sedi» (il contesto
  normalizza a `[]` anche la scelta esplicita di tutte): `selezionate.length > 1` darebbe `false`
  proprio con tre sedi visibili. `effettive` è l'elenco vero (sottoinsieme scelto ∩ accessibili, o
  tutte).
- **Difesa nel componente**: se le `classi` coprono più di uno `scuolaId`, la sede si mostra
  comunque (`conSede = mostraSede || new Set(classi.map(c => c.scuolaId)).size > 1`): gruppi per sede
  e sede nel nome accessibile e nel riepilogo. Due pastiglie «Sezione A» identiche di plessi diversi
  non si disegnano mai, qualunque `mostraSede` passi il genitore.
- **Id ripetuti** in `selezionate` contano **una volta sola** (deduplicati prima di riepilogo,
  conteggio e `aria-pressed`): `['g-a','g-a']` → riepilogo «Sezione A», non «2 classi». `onChange`
  restituisce id senza ripetizioni.
- **Classe senza nome** (`nome === NOME_CLASSE_ASSENTE`): il componente mostra «Classe senza nome» /
  «Unnamed class» (`filtroClassiSenzaNome`) nel testo della pastiglia, nel nome accessibile
  («Classe senza nome — Giugliano» con più sedi) e nel riepilogo. Il simbolo `'—'` non arriva mai a
  schermo.

- **Controllato**: nessuno stato interno sulla selezione; lo tiene il genitore (che lo manda anche
  all'export come `section_ids`). Unico stato interno: pannello aperto/chiuso.
- **Comando**: etichetta visibile «Classe» + riepilogo nel bottone. Nome accessibile
  `"Classe <riepilogo>"`. Il riepilogo si calcola sugli id **validi** (quelli di `selezionate` che
  corrispondono a una voce di `classi`): `selezionate` vuota → «Tutte le classi»; nessun id valido ma
  `selezionate` non vuota → «Classi non più disponibili»; un valido → la sua etichetta (vedi sotto);
  più di uno → «N classi» (plurale ICU, N = validi).
- **Id scaduti** (in `selezionate` ma non in `classi`): non contano per riepilogo e `aria-pressed`, e
  il primo tocco su una pastiglia li butta via (`onChange` riceve solo id validi). «Tutte le classi»
  ha `aria-pressed` = `selezionate.length === 0` (lo stato vero del genitore), e resta sempre
  raggiungibile per azzerare.
- **Pannello** (disclosure, pattern di `ui/BarraFiltri`): `aria-expanded` + `aria-controls`, sempre
  nel DOM con `hidden`, `role="group"`. Escape e clic fuori chiudono; con Escape il fuoco torna al
  comando. Un clic DENTRO il pannello (mousedown compreso) lo lascia aperto: è ciò che rende possibile
  la selezione multipla col mouse, e per questo il pannello deve restare dentro il contenitore del
  componente (niente portal).
- **Dentro il pannello**: pastiglia «Tutte le classi» (`aria-pressed` = nessuna selezione, click →
  `onChange([])`), poi un `fieldset` per sede con `legend` = nome della sede (con la sede mostrata: `conSede`), o un
  unico `fieldset` «Classi». Ogni classe è una pastiglia `aria-pressed`; click aggiunge o toglie l'id
  (`onChange` con l'array nuovo, ordine di inserimento). Con `conSede` il nome accessibile della
  pastiglia è `"<classe> — <sede>"`.
- **Sede senza nome** (`scuolaNome: ''`, con `conSede`): il componente non lascia legende vuote né
  trattini appesi. Le sedi ignote restano **gruppi distinti per `scuolaId`** (fonderle unirebbe le
  omonime, contro la decisione del titolare), con legenda «Sede non indicata» se è una sola, «Sede non
  indicata 1», «Sede non indicata 2»… se sono più d'una (numerate nell'ordine di `classi`). Lo stesso
  nome di ripiego entra nel nome accessibile della pastiglia e nel riepilogo
  («Sezione A — Sede non indicata 2»). Senza `conSede` resta il gruppo unico «Classi».
- Si disegna **`null` solo con `classi` vuote E `selezionate` vuota**. Con `classi` vuote ma una
  selezione attiva il comando resta, con dentro soltanto «Tutte le classi»: altrimenti un filtro
  scaduto azzererebbe la lista senza più un comando per toglierlo.
- **Telefono** (sotto `sm`): il pannello scende nel flusso a piena larghezza; il comando è alto 44px
  (`max-sm:h-[44px]`) e le pastiglie usano `BERSAGLIO_TOCCO` di `ui/FoglioFiltri`, annullato da `sm`
  in su (`sm:min-h-0`). Da `sm` in su il pannello galleggia sotto il comando (360px).

## Uso previsto (P2, `PaymentsDashboard`)

```ts
// Da `useSediAttive()` (src/lib/context/sede-context.tsx). `sedi` = sedi accessibili {id, nome};
// `effettive` = le sedi VISIBILI. NON usare `selezionate`: vuoto vuol dire «tutte».
const { sedi, effettive } = useSediAttive();
const nomiSedi = useMemo(() => Object.fromEntries(sedi.map((s) => [s.id, s.nome])), [sedi]);

const classi = useMemo(
  () =>
    classiDaAlunni(
      righe.flatMap((p) =>
        p.alunni
          ? [{ section_id: p.alunni.section_id ?? null, classe_sezione: p.alunni.classe_sezione ?? null, scuola_id: p.scuola_id ?? null }]
          : [],
      ),
      nomiSedi,
    ),
  [righe, nomiSedi],
);
// Gli id scelti che non corrispondono più a una classe in elenco (cambio di sede, righe
// ricaricate) si SCARTANO prima di usarli, e la stessa lista va a filtro, export e componente.
// Deduplicati: un id ripetuto non deve finire due volte in `section_ids`.
const scelteValide = useMemo(
  () => [...new Set(classiScelte)].filter((id) => classi.some((c) => c.id === id)),
  [classiScelte, classi],
);
const visibili = filtraPerClassi(righe, scelteValide, (p) => p.alunni?.section_id ?? null);
// export: se scelteValide.length > 0 → ?section_ids=<id1>,<id2>

<FiltroClassiContabilita
  classi={classi}
  selezionate={scelteValide}
  onChange={setClassiScelte}
  mostraSede={effettive.length > 1}
/>
```

**Scelta: scartare, non azzerare.** Lo stato `classiScelte` NON si azzera al cambio di sede: si
filtra in lettura (`scelteValide`). Così `filtraPerClassi` non esclude mai tutte le righe per un id
che non esiste più, il comando non annuncia classi invisibili, e tornando alla sede di prima la scelta
ricompare (se nel frattempo il filtro non è stato toccato: `onChange` restituisce solo id validi). Passare a `filtraPerClassi` o all'export `classiScelte` grezzo invece di `scelteValide` è
il difetto da evitare: un id scaduto svuoterebbe la lista. Il componente regge comunque anche un
genitore che non scarta (vedi «Id scaduti» sopra), ma il filtro delle righe sta nel genitore e lì il
componente non arriva.

**La sede si prende dalla riga di pagamento (`p.scuola_id`), non dal join `alunni`.** Il join di
`src/app/api/pagamenti/route.ts` (`alunni ( id, nome, cognome, codice_fiscale, classe_sezione,
section_id, sospeso )`) non porta `scuola_id`: passare `p.alunni` così com'è non compila, e
adattato con un cast darebbe `scuolaId: ''` a tutte le classi, fondendo le omonime di sedi diverse in
un gruppo solo con etichette identiche — il contrario della decisione del titolare. **Le righe senza
alunno (`p.alunni` nullo) vanno scartate** (`flatMap` → `[]`).
